# Menu Hub MVP 对照验收

更新时间：2026-09-08

## 结论

对照原产品与工程规格，MVP 的主要产品模块已经有实现，之前缺失的完整目录、搜索、智能组、快捷键、面板、渐进授权、管理/设置、双语和诊断均已进入代码库。

本地验收版现已通过 238 项 XCTest 与 2 项 Swift Testing，完成 `arm64` / `x86_64` 独立 Release 构建和 DMG/ZIP 验证，并将本机 `arm64` 副本以 Developer ID 签名后安装运行。仍不能标记为正式公证公开版：缺口集中在完整 UI 自动化、Phase 0 硬件/耐久矩阵和 Apple 公证，而不是继续堆功能。

## 与规格仍有差距

### 公开发布阻断

- 独立 UI Test target 尚未形成完整可重复结果，权限测试必须使用 fixture，不能修改真实 TCC。
- 最终 SwiftPM、Release build、签名和安装门禁已经记录；独立 Xcode UI 测试因当前 Mac 锁屏未形成可信结果。
- 滚动条布局和飞书名称/数字同步已有代码、测试及实时目录证据；解锁后仍需完成像素/手感截图验收。
- 15 项代表性兼容矩阵、最低支持 macOS 与最新稳定 macOS 的硬件验证未完成。
- 长时间、循环、睡眠/唤醒、显示器插拔和 SystemUIServer 重启测试未完成。
- Developer ID 签名可以用于本地验收，但 Apple 公证、stapling、Gatekeeper 和干净 Mac 验证未完成。

### 需要以实测数字关闭

- Apple Silicon 冷启动到图标 < 500 ms。
- 热态打开面板 P95 < 100 ms。
- 100 项搜索 < 16 ms。
- 空闲 CPU < 0.2%，稳态内存 < 45 MB。
- 未压缩 App < 15 MB，压缩包 < 8 MB。

## 英文版本与授权体验

用户可在“设置 > 通用 > 语言”选择 System Default、简体中文或 English。语言偏好保存在本机；需要重新打开的菜单或窗口会由界面提示。

Accessibility 采用渐进授权：用户先看到用途和本地隐私说明，可选择跳过；未授权时仍可打开已知宿主 App。授权后回到应用会自动重检，不应反复催促。只有系统授权记录疑似与 Bundle ID/签名不一致时，才向用户提供显式 repair，并在二次确认后只重置 Menu Hub 自己的记录。

## 公开 API 边界

原规格对此判断仍然成立：macOS 没有公开 API 可以保证 Menu Hub 枚举、移动、隐藏和代理所有状态项。透明 SpacerItem 可以改变可见空间，但不能强制靠近系统图标或任意重排；Accessibility 质量由目标 App 决定；系统项目和未暴露语义的第三方项目可能只能启动宿主或不可用。

因此，发布文案必须使用“对兼容项目可触发，并提供启动降级”，不能使用“支持所有图标”“完全接管菜单栏”。
